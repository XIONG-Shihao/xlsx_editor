# Roadmap

The [goal](README.md#the-goal): everyday spreadsheet work on real Excel files, with nothing lost in
either direction. These are the big steps toward it, in order. Each says what "done" means in a way
that can be measured.

## Where it stands

**A standing set of real workbooks, and a scoreboard.** 101 workbooks: 75 public files from
government and open-data sources in five places, and 26 made here to cover what those lack (charts,
array formulas, notes, dropdowns, grouping, protection, sheet names in other scripts), then saved by
Excel. One command measures the editor against all of them. Workbooks generated by the editor's own
tests hide most of what goes wrong on real files, which is why the set uses real ones.

| Measure | Now |
|---|---:|
| Everyday actions that work | 92.6% |
| ...or are refused exactly where Excel refuses too | 95.4% |
| Workbooks that open for editing | 100 |
| Round trips with nothing lost | 97 of 97 |
| Files Excel accepted | 94 of 94 |
| Moving actions that match Excel doing the same action | 474 of 525 |

**Each action is compared with Excel doing the same action** (the last row). Where the editor
still differs, the differences are listed, with reasons, in
[Working with Excel in both directions](BIDIRECTIONAL_COMPATIBILITY.md#rule-3-do-what-excel-does).

## Step 1: reach 95% on the set

**Where it stands.** 92.6% of everyday actions work (2,669 of 2,883). Another 81 are refused on protected sheets,
where Excel refuses the same action; counting those as right answers, 95.4%. By the strict count the
target is 2.4 points away. The largest single step left is the workbook with macros (1 point).

The Excel rows (files accepted, actions matching Excel) come from the last full run with Excel; the
action counts were measured again afterwards, without Excel. The changes made in between were
compared with Excel on the eight workbooks they affect: 45 of 50 actions matched.

What is still refused, by how many of the 101 workbooks it affects:

| Workbooks | What is refused | Why it is still refused |
|---:|---|---|
| 3 | Every change on a protected sheet (81 actions) | Excel refuses these too. Counted as agreeing with Excel, not as working |
| 1 | Everything, on a workbook that contains macros (30 actions) | Now editable; not yet measured again |
| 11 | Sorting when a note sits on the sorted rows, when formulas on other sheets point into them, or when a pivot table is on the sheet | The note or the reference would have to follow its row |
| 9 | Adding a note on a sheet that arrived with notes | The editor only writes notes into note records it started |
| 2 | Inserting or deleting rows on a sheet with extended dropdowns | Ranges inside extension records are not moved yet |
| 2 | Inserting or deleting rows on a sheet with shapes or text boxes | Only pictures and charts follow their rows |
| 1 | Layout changes on one workbook (11 actions) | Two parts of the editor disagree about its names; not yet diagnosed |
| about 20 | One action each: formula forms the editor does not rewrite (dynamic arrays, grouped formulas), deleting the rows a chart sits on, filling from a merged cell, a sheet too large for one request | Each is a separate small cause |

**Decided: macro workbooks are edited.** Excel edits such workbooks and leaves the macros alone;
the editor now does the same, carrying the macro part and its type unchanged (a test checks both).
The next measurement should show the 30 actions above as working.

**Done when** 95% of everyday actions succeed across the set and every remaining refusal has a
message a person can act on. A change counts as done only when the
[gate](DEVELOPMENT.md#the-definition-of-done) passes: no workbook may get worse.

## Step 2: the app in a person's hands

**What.** Everything above is measured without opening a window. Walk the
[feature checklist](FEATURES.md) in the built app, by hand, on a few workbooks from the set: what a
refusal looks like, speed on large files, Undo, recovery, printing. Two rows of the checklist
(printing to paper, spelling) are checked by nothing else.

**Done when** a person has completed the list in the built app and what they found is fixed.

## Step 3: speed on real files

**What.** Real workbooks are slow in ways generated ones are not. A workbook with a large styles
section still takes 6 seconds to open, and the editor re-reads the workbook's structure for every
action, so each action on such a file takes seconds. On the largest workbooks in the set the
measurement ran out of its four-minute allowance before finishing 30 actions.

**Done when** opening any workbook in the set takes under 2 seconds and an everyday action on it
under 1 second, measured by the same tool.

## Step 4: widen "everyday"

**What.** The measurement uses 30 actions. Grow it to cover the everyday rows of the
[feature checklist](FEATURES.md) that it does not touch yet: paste variants, fill series, find and
replace, data validation, charts, print setup, names. 17 of the 64 rows are measured today.

**Done when** each everyday row is exercised by at least one measured action.

## Step 5: calculate more, never wrongly

**What.** Count which functions the formulas in the set use and which of those the calculator
declines. Add the most used, each checked against results Excel stored. Keep the rule that the
calculator may decline but may not be wrong; a test enforces it today on 620 reference results.

**Done when** 95% of the formulas in the set calculate, with no wrong answer.

## Step 6: simpler machinery

**What.** Each rule in one place, every refusal with a code, and small modules instead of files that
handle everything.

**Where it stands.**

- Moving a sheet's records, and the parts beside a sheet when rows and columns move (names, tables,
  notes, pictures, charts), is planned once, in the Rust engine.
- Every refusal carries a code (240 codes); tests check the code, not the wording.
- Commands go through a 79-line dispatch to 26 modules, one per command family; the screen file is
  2,191 lines with 60 modules beside it.
- Indexed workbooks ask the engine what they contain (sheets, names, tables, styles, filters, rules,
  what keeps them from being edited); a test holds the engine's answer to the JavaScript reader's on
  every fixture.
- A change counts as done when it passes the gate on the 101 workbooks.

**Still to do.** The in-memory path and a few planning helpers still read the cell-free copy in
JavaScript. Components still hand each other receipts and hashes in places where a check at the edge
would do.

**Done when** a rule such as "deleting a row deletes the link on it" is written in one place, and
the JavaScript layer no longer parses workbook files.

## Later, not now

- Larger sample libraries for shapes, icons, themes and the rest of
  [FEATURES_SAMPLES.md](FEATURES_SAMPLES.md).
- Windows and Linux builds; signed public releases.
- Anything under "What is left out" in the [feature checklist](FEATURES.md#what-is-left-out) stays out
  unless the goal changes.
